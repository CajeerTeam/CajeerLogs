# Project & Source Management — 0.3.8

## Каталог и доступ

В разделе «Проекты и источники» каталог проектов имеет независимые фильтры имени, slug, UUID и статуса, серверную курсорную навигацию. Выбор проекта меняет рабочую область и очищает фильтры Explorer. Администратор управляет проектами и участниками; оператор с эффективной ролью operator управляет источниками и токенами. Viewer только читает доступные проекты. Все операции проверяются существующим серверным RBAC.

Источники фильтруются по имени/slug/UUID, статусу и `source_type` (`application`, `server`, `nginx`, `aapanel`, `custom`, `all`). Порог активности (1–10080 минут) применяется к `last_seen_at`, не является проверкой доступности по сети. Счётчики accepted/rejected накопительные; количество сохранённых событий уменьшается при retention. Источник после восстановления остаётся disabled. Архивный проект блокирует ingest, но история доступна.

## Политики и статистика

Карточка источника показывает проектный и индивидуальный retention, ограничения размера и пакета (минимум из применимых), независимые квоты проекта и источника. Глобальные лимиты и текущий остаток квоты не вычисляются UI. Retention удаляет записи, удовлетворяющие любому из двух ограничений; действует минимальный заданный срок. Правила redaction и предпросмотр сохраняют существующий API. Статистика проекта показывает распределение источников по статусам, количество сохранённых событий, 24-часовой объём по received_at, очередь и dead-letter. Карточка источника показывает отдельные счётчики и обновление по запросу. 

## Подключение

1. Выберите активный проект. Откройте «Мастер подключения» или «Подключить приложение» у активного источника.
2. Создайте источник (имя, slug, тип), если необходимо. Выдайте ограниченный `logs:write` токен на 1–365 дней. HMAC v1 подписывает Bearer-секретом, HMAC v2 — отдельным ключом. Для v2 нужен настроенный серверный ключ шифрования signing keys.
3. Сохраните одноразово показанные credentials в защищённом хранилище приложения. Скопируйте Python/HTTP пример; он использует стандартную библиотеку, текущий URL API и секреты окружения `CAJEER_TOKEN`, `CAJEER_SIGNING_KEY_ID`, `CAJEER_SIGNING_SECRET`. Пример запрещает HTTP redirects; production требует HTTPS.
4. «Проверить подключение» проверяет токен, отправляет синхронный подписанный INFO-лог с уникальным request_id и Idempotency-Key, подтверждает receipt и читает сохранённое событие через текущую сессию. При повторе в том же мастере тело и ключ идентичны, nonce/подпись новые. Отдельная кнопка открывает Explorer по источнику и сохранённому request_id; отдельная кнопка открывает инспектор точного UUID, даже если redaction замаскировал идентификатор корреляции. Событие расходует квоту и хранится по обычному retention.

Создание источника и выпуск токена — отдельные транзакции. Закрытие мастера не удаляет ресурсы, секреты не сохраняются в браузерном хранилище. При потере ответа выпуска проверьте список токенов и отзовите недоступный секрет перед повтором. Мастер не выполняет фоновые автоматические повторы. Если срок идемпотентности истёк, повтор может создать новое событие. Не оставляйте мастер открытым надолго. Проверка доставки требует защищённого браузерного контекста (HTTPS или localhost).

## API и обновление

`GET /api/v1/projects/{project}/sources` принимает `source_type`; поиск `q` проектов и источников включает UUID. `GET /api/v1/projects/{project}/stats` возвращает `active_sources`, `disabled_sources`, `archived_sources` дополнительно к существующим полям. Новых маршрутов и миграций нет. API v1, SDK wire protocol и миграции 0001–0016 сохраняются.

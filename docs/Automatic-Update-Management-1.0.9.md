# Автоматическое управление обновлениями

> Добавлено в 1.0.9. По умолчанию выключено. Не требует новых миграций.

## Выбор режима

| Режим | Действия | Канал |
|---|---|---|
| `off` | Автоматизация выключена | — |
| `check` | Проверка выпусков и уведомления | `stable` / `preview` |
| `download` | Дополнительно загрузка и верификация | `stable` / `preview` |
| `install` | Безопасная установка в заданном окне | Только `stable` |

Планировщик использует действующие обнаружение, криптографическую проверку и нативный установщик. Веб-панель показывает состояние и уведомления, но не управляет привилегированными командами. Docker, распределённые и разделённые по ролям установки требуют отдельного процесса развёртывания. Ознакомьтесь с [требованиями безопасной установки](Safe-Update-Installation-1.0.3.md), особенно с полномочиями systemd.

## Включение проверок

```sh
php bin/cajeer update:auto-configure --mode check --channel stable --interval-minutes 60
php bin/cajeer update:auto-tick
php bin/cajeer update:auto-status
php bin/cajeer update:auto-configure --mode download --channel preview --interval-minutes 120
php bin/cajeer update:auto-configure --mode off
```

Политика планировщика независима от `UPDATE_CHANNEL` ручной проверки. Для одинакового канала задайте переменную или `update:check --channel=preview`. При ошибке проверка не считается успешной и повторяется согласно интервалу; отсутствие новых выпусков не является ошибкой. Кандидат повторно обнаруживается непосредственно перед установкой, отозванный выпуск не применяется. Загрузка конкретной версии требует, чтобы она оставалась новейшим кандидатом своего канала.

Примеры `cajeerlogs-auto-update.service` и `cajeerlogs-auto-update.timer` находятся в `examples/systemd/`. Укажите реальные учётную запись, группу, канонический каталог и перечень служб. Разместите определения под контролем администратора и включите только таймер:

```sh
systemctl daemon-reload
systemctl enable --now cajeerlogs-auto-update.timer
```

Таймер вызывает проверку политики раз в минуту, фактические сетевые проверки зависят от интервала. Сам таймер и его службу не включайте в перечень останавливаемых компонентов. Для проверки и загрузки не нужны полномочия systemctl. Не запускайте параллельно другие развёртывания.

## Установка по расписанию

Создайте заранее несколько отдельных пустых БД во владении роли приложения. Каждая попытка установки навсегда расходует имя из пула; не используйте его повторно после ошибки или восстановления. Окно ежедневно задаётся в UTC, допускается переход через полночь и ограничивается только временем **начала**, а не длительностью операции. Уже начатое резервное копирование/миграция не прерывается по окончании окна.

```sh
php bin/cajeer update:auto-configure --mode install --channel stable \
  --interval-minutes 60 --window-start 03:00 --window-minutes 60 \
  --target-db cajeer_logs_next_a --target-db cajeer_logs_next_b \
  --unit cajeerlogs-web.service --unit cajeerlogs-queue.service \
  --unit cajeerlogs-scheduler.service --unit cajeerlogs-scheduler.timer \
  --unit cajeerlogs-webhook.service --unit cajeerlogs-webhook.timer \
  --sudo-systemctl --confirm
```

Замените пример полным списком всех служб и активаторов своего хоста. Нужны предварительно проверенные подписанные артефакты, пустая БД, достаточное место и узкие права оператора. Не задавайте внешние переопределения `DB_*`, `APP_URL`, `BACKUP_DIR`, `CAJEER_ENV_FILE` или версии для установки. При исчерпании пула операция блокируется; создайте новые БД, обновите политику и явно возобновите работу. Не включайте автоматическую установку на недоверенном совместно используемом сервере.

## Уведомления и сбои

Раздел «Система» показывает режим, окно UTC, предыдущую и следующую проверку, кандидат, проверенный ZIP, оставшиеся имена БД, сигнал активности и последние 20 уведомлений. Доступ только для чтения через `system:read`. Уведомления также доступны в журнале systemd; отдельная почта не требуется. Устаревший сигнал может означать остановку таймера или долгую установку.

Закрытые политика и состояние находятся в `.current.automatic-update/` (`0700`) вне переключаемого каталога. Веб-запросы не записывают их. Не удаляйте состояние при работающем планировщике. Параллельный запуск не дублирует установку. Сбой или прерывание блокирует последующие автоматические попытки.

```sh
php bin/cajeer update:status
php bin/cajeer update:recover --confirm
php bin/cajeer update:auto-resume --confirm
```

При необходимости примените `--sudo-systemctl` к восстановлению. Возобновление проверяет журнал установщика, поэтому незавершённая операция требует восстановления сначала. До фиксации допускается возврат исходной версии; после фиксации — только завершение на новой БД без потери принятых записей. Для отключения будущих запусков задайте `--mode off` или отключите таймер; не завершайте принудительно активную установку. Сначала проведите полную репетицию реального подписанного обновления на целевом хосте.

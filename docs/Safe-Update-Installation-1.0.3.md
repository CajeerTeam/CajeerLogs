# Безопасная установка обновления

> Добавлена в 1.0.3. Операторская установка на отдельном Linux/systemd-сервере.

## Поддерживаемое размещение

- Одиночная нативная установка 1.0.3+ в обычном каноническом каталоге, например `/srv/cajeerlogs/current`, не в символической ссылке и не на отдельной точке монтирования. Родитель принадлежит выделенному оператору и недоступен на запись группе или всем пользователям.
- `.env` и `storage/` принадлежат той же учётной записи; хранилище не содержит символических/жёстких ссылок, устройств и отдельных монтирований. Используется локальное хранилище резервных копий по умолчанию. Произвольные файлы вне `.env` и `storage/` не копируются: они остаются в прежнем каталоге.
- Одна выделенная PostgreSQL БД во владении роли приложения. Docker, кластер, разделённые роли, внешний файл окружения и многосерверные записывающие процессы не поддерживаются этим установщиком; используйте [операторское обновление](Installation.md).
- Linux с `renameat2(RENAME_EXCHANGE)`, Python 3.11+, PHP 8.4+ с PDO PostgreSQL/ZIP, Composer, совместимые `pg_dump`/`pg_restore`, GitHub CLI с аттестациями, TLS и доступ к репозиториям пакетов.

Запускайте от выделенного оператора, не от root и не из HTTP. Службы должны иметь определения, принадлежащие администратору, в `/usr/lib/systemd/system` либо `/lib/systemd/system` для создания постоянных масок в `/etc/systemd/system`. Не предоставляйте веб-процессу неограниченный `sudo`. Если нужны полномочия, делегируйте только конкретные `systemctl`-операции для согласованных служб. Секреты храните отдельно.

## Подготовка

Составьте **полный** перечень входящего трафика, PHP-FPM, обработчиков очереди, планировщиков, экспорта, вебхуков, резервного копирования, репликации и всех активирующих таймеров/сокетов/путей, включая неактивные. Они должны запускать канонический каталог и читать его `.env` без переопределения БД или версии. Не добавляйте PostgreSQL, SSH и посторонние общие службы. Остановите внешних писателей, задания cron и другие экземпляры; ни один посторонний клиент не должен подключаться к исходной или целевой БД во время работ. Проверка исходной БД отклоняет посторонние активные клиентские подключения.

Подготовьте новую **действительно пустую** БД на том же сервере, принадлежащую роли приложения. Установщик не создаёт и не удаляет базы. Требуется место для второй БД, копии, нового дистрибутива и хранилища. Сохраните исходную БД и прежний релиз. Пример SQL в административной сессии (замените имя и роль):

```sql
CREATE DATABASE cajeer_logs_next OWNER cajeer_logs;
```

## Установка

Пример для опубликованной будущей версии, подставьте реальную версию в `VERSION` и перечислите все службы именно своего размещения:

```sh
cd /srv/cajeerlogs/current
php bin/cajeer update:check --refresh
php bin/cajeer update:download --refresh
php bin/cajeer update:verify VERSION
php bin/cajeer update:install VERSION --target-db cajeer_logs_next \
  --unit cajeerlogs-web.service --unit cajeerlogs-queue.service \
  --unit cajeerlogs-scheduler.service --unit cajeerlogs-scheduler.timer \
  --unit cajeerlogs-webhook.service --unit cajeerlogs-webhook.timer \
  --unit cajeerlogs-export-worker.service --unit cajeerlogs-export-worker.timer \
  --unit cajeerlogs-export-cleanup.service --unit cajeerlogs-export-cleanup.timer \
  --unit cajeerlogs-backup.service --unit cajeerlogs-backup.timer \
  --unit cajeerlogs-analytics-replication.service --unit cajeerlogs-analytics-replication.timer \
  --sudo-systemctl --confirm
```

Перечень иллюстративен, не универсален. `--sudo-systemctl` необязателен, если у оператора есть нужные права. Установщик повторно проверяет подписанный ZIP, копирует в закрытый каталог, проверяет хэш и манифест, устанавливает закреплённые зависимости Composer без скриптов и плагинов, останавливает и маскирует перечисленные службы. Создаёт и проверяет резервную копию, восстанавливает изолированный клон (учётные записи и токены сохраняются только для обслуживаемого клона), копирует приватные файлы, меняет только `DB_DATABASE` в новой `.env`, выполняет миграции через `upgrade BACKUP_ID --confirm-stopped`, сверяет схему, эксклюзивность и готовность. После синхронизации атомарно обменивает каталоги, записывает фиксацию и возобновляет ранее активные службы. HTTPS `/ready` должен подтвердить точную версию; проверяется и состояние служб. При обычном аварийном восстановлении восстановленные полномочия отзываются по штатным правилам.

## Восстановление

```sh
php bin/cajeer update:status
php bin/cajeer update:recover --sudo-systemctl --confirm
```

Журнал `.current.safe-update/` в соседнем приватном каталоге хранит состояние операции, старый выпуск, его конфигурацию/хранилище и копию кандидата. Не удаляйте его, не меняйте каталоги вручную и не снимайте маски при незавершённой операции. До долговечной фиксации возможно восстановление прежнего приложения и исходной неизменённой БД. После фиксации необходимо завершить запуск новой БД, не возвращаться к старой и не уничтожать новые записи. Не используйте испробованную целевую БД повторно. Проверьте фактическое состояние, устраните причину, затем используйте журнал восстановления. Полноценная приёмка требует репетиции на настоящем поддерживаемом хосте.

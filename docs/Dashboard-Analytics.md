# Dashboard & Analytics — 0.3.3

## Работа панели

Откройте «Обзор», выберите проект, затем период (15 минут, 1/6/24 часа, 7/30 дней или свой диапазон до 31 дня), группировку и источник. Источники доступны из списка с поиском, фильтром статуса и курсорной пагинацией. Кнопка «Выбрать» применяет источник к метрикам, графику и последним событиям. «Все источники» снимает ограничение. Параметры хранятся в памяти текущего сеанса, очищаются при смене проекта/выходе; секретов в localStorage нет.

- Метрики: все события, ошибки (error/critical/alert/emergency), warnings, процент ошибок, среднее событий в минуту, источники с событиями. Показатели относятся к `occurred_at`, не к времени приёма.
- Сравнение: предыдущий равный по длительности диапазон `[from-duration,from)`. Доля ошибок сравнивается в процентных пунктах. При нулевой базе не выдаётся бесконечный процент.
- График: пустые интервалы заполняются нулями, крайние интервалы ограничены исходным диапазоном. Наведение/фокус показывает объём, ошибки и границы; Enter/нажатие открывает Explorer с теми же проектом, источником и UTC-границами. Таблица под графиком позволяет перейти отдельно к ошибкам.
- Топ-10 по источникам, сервисам и хостам; нажатие применяет точный фильтр. Распределение по восьми уровням PSR-3. Последние события или только critical/alert/emergency.
- Состояние источников: текущий административный статус, `last_seen_at` (последний принятый ingest, включая очередь), суммарные счётчики приёма и отказов. Активный источник с давним last_seen отмечается как не получавший недавние события; это не монитор доступности приложения. Статусы отражают настоящее, независимо от исторического периода графика. Архивный проект не принимает новые события.
- Ручное обновление, опциональное обновление через 60 секунд (без параллельных циклов, отменяется при уходе со страницы/сессии; при скрытой вкладке или изменении неприменённой формы приостанавливается). Пользовательский период остаётся фиксированным. При сбое отдельного запроса показывается ошибка соответствующего блока вместо нулевых данных.

## Backend

`GET /api/v1/logs/stats?project_id=...&from=...&to=...&interval=5min` использует существующий LogQuery, PostgreSQL LogRepository, SearchRuntime, rate limiter, проверку проекта и области source-scoped токена. Все группировки вычисляются одним SQL statement по одному snapshot, без передачи сырых логов для подсчёта в браузере. Границы UTC полуоткрытые: `[from,to)`.

| interval | Максимальный диапазон |
|---|---|
| minute | 6 часов |
| 5min | 2 дня |
| hour / day | 31 день |

Существующие поля ответа сохранены. Добавлены `source_count` (количество групп источников до ограничения top-100), `by_service`, `by_host` (до 10 непустых групп) и `buckets[].errors`. Разбиение по времени использует `date_trunc` или `date_bin`; пустые buckets на сервере не создаются. При сравнении и загрузке последних событий/источников выполняются отдельные запросы: их снимки могут немного различаться при одновременном ingest. Тяжёлые запросы ограничены существующим SQL-бюджетом; при 503 следует сузить период или выбрать источник. Отдельных rollup-таблиц и фоновых процессов нет.

## Обновление и проверка

Обновление 0.3.2 → 0.3.3 не добавляет миграций. Сохраняются миграции 0001–0015, сессии, API-токены, SDK wire-контракты и backup compatibility. Распакуйте changed-files ZIP поверх корня; проверьте `php bin/cajeer version`, `php bin/cajeer migrate:verify`, `php bin/cajeer openapi:lint`, `npm --prefix admin run build`. При контейнерном развёртывании пересоберите образ. Модульные пути и версии обновляются атомарно; `.gitignore` теперь разрешает отслеживание production JS/CSS подкаталогов.

Тесты: `php tests/search.php`, `php tests/search_database.php` (disposable PostgreSQL), `npm --prefix admin run build`, `python tests/admin_browser.py`, `python tests/admin_browser_database.py` (реальная БД). Канал public-preview до прохождения полного release gate.

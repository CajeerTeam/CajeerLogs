# Проверенная загрузка дистрибутивов

> Добавлена в 1.0.2; в 1.1.0 усилена проверкой итогового сертификата стабильного выпуска.

## Требования и команды

Нужны PHP 8.4+, `ext-zip`, доступная PostgreSQL 17/18 через PDO, официальный GitHub CLI с `gh attestation verify` и исходящий HTTPS к GitHub и сервисам аттестации. В поставляемом production Dockerfile предусмотрены ZIP и GitHub CLI. При необходимости задайте `GH_TOKEN` с минимальными правами чтения только в окружении операторского процесса, не в публичном файле. Кэш доверенных корневых данных Sigstore изолирован в приватном `storage/archives/verified-updates/.gh-cache`. Для диагностики применяйте `gh auth status` и `gh attestation verify --help`.

```sh
php bin/cajeer update:check --refresh
php bin/cajeer update:download --refresh
php bin/cajeer update:verify VERSION
```

Замените `VERSION` фактически опубликованной и скачанной версией. Загрузка выбирает только более новый кандидат в соответствующем канале. Получает `CajeerLogs-VERSION.zip` и `CajeerLogs-VERSION.zip.sha256` через GitHub CLI во временный приватный каталог. Данные GitHub подтверждают принадлежность файлов опубликованному тегу с прямой ссылкой на коммит.

## Что проверяется

1. SHA-256 ZIP совпадает с контрольной суммой и, при наличии, с digest файла GitHub.
2. Криптографическая аттестация подтверждает точные репозиторий, тег, коммит и workflow. Применяется доверенный GitHub-hosted runner и предикат SLSA:

```sh
gh attestation verify ZIP --repo CajeerTeam/CajeerLogs \
  --source-ref refs/tags/vVERSION --source-digest COMMIT_SHA \
  --signer-workflow CajeerTeam/CajeerLogs/.github/workflows/runtime.yml \
  --deny-self-hosted-runners --predicate-type https://slsa.dev/provenance/v1 --format json
```

3. В версии 1.1.0 для stable дополнительно требуется отдельно аттестованный успешный `database-certification.json`, привязанный к тому же ZIP, тегу, коммиту и workflow.
4. Проверяются `RELEASE-MANIFEST.json`, отсутствие повторных записей, обхода путей и символических ссылок, размер и хэш каждого файла, версия CajeerLogs, API v1, совместимость PHP и фактической PostgreSQL.
5. Лишь после успеха файлы атомарно помещаются в `storage/archives/verified-updates/vVERSION/` с приватными правами.

`update:verify` повторяет сетевую проверку происхождения, тега, совместимости и целостности. Панель «Система» с `system:read` позволяет получить уже проверенный ZIP; изменённый или отсутствующий файл не выдаётся как проверенный. Эти команды не устанавливают приложение.

## Отказы

Неподписанный выпуск, недоступный проверяющий инструмент, неверные хэши, отсутствующие файлы, несовместимый runtime, отозванный выпуск или неполный сертификат блокируют операцию. Частичные загрузки удаляются. Повреждённый ранее сохранённый каталог не перезаписывается автоматически: оператор расследует и изолирует его. Если старый кэш stable не содержит нового обязательного сертификата, остановите таймер и изолируйте только такой каталог версии, затем загрузите заново. Подпись нельзя отключать ради установки.

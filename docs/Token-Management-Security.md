# Token Management & Security — 0.3.9

В разделе «API-токены» доступны проектные credentials и (для Administrator) системные credentials. Operator управляет токенами только в проектах с эффективной ролью Operator. Viewer и Bearer-клиенты не имеют доступа к административным операциям.

## Каталог и сервисные аккаунты

Серверные фильтры токенов: `q` (имя/UUID, буквальный регистронезависимый поиск), `scope`, `status=all|active|expiring|expired|revoked`, `source_id`, `service_account_id`, `limit`, `cursor`. `expiring` означает активный токен с истечением в ближайшие семь дней по серверному времени. `GET /projects/{project}/tokens/{token}` и `GET /system/tokens/{token}` возвращают метаданные, predecessor/successor и действующий режим подписи, без секретов. Источники и аккаунты ограничены проектом; фильтр UUID поддерживает записи за пределами первой страницы реестра.

Сервисные аккаунты поддерживают `q`, `status=all|active|disabled` и курсорную пагинацию. `GET /projects/{project}/service-accounts/{account}` возвращает метаданные, число всех и активных токенов и последнее использование; карточка открывает выборку токенов сервиса. Отключение необратимо и отзывает все связанные credentials. Для повторного подключения создайте новый сервисный аккаунт. Last used обновляется с интервалом до пяти минут, счётчики не являются точным онлайн-мониторингом.

## Ротация

1. Выпустите ограниченный scopes/источником токен либо замену текущего с минимально необходимым overlap. Ротация не расширяет scopes и сохраняет источник/сервисный аккаунт. Если включён отдельный HMAC v2, новый Bearer получает собственный ключ.
2. Сохраните выданные секреты непосредственно в secret manager приложения. Они показаны один раз; не помещайте их в URL, логи или репозиторий. В случае потерянного ответа проверьте каталог, отзовите недоступный секрет и создайте замену.
3. Переключите приложение, проверьте подписанный ingest через мастер подключения/SDK и затем отзовите старый токен. Уже принятые задания очереди могут завершиться после отзыва. Не увеличивайте overlap для завершения уже принятой сервером работы.
4. Для отдельной ротации HMAC v2 откройте «HMAC» у активного write-токена. Первый отдельный ключ сразу отключает v1 для этого токена; последующая ротация оставляет максимум один предыдущий ключ. Досрочное завершение overlap: `DELETE /api/v1/projects/{project}/tokens/{token}/signing/previous` с JSON `{"expected_key_id":"CURRENT_UUID","expected_previous_key_id":"PREVIOUS_UUID"}`. Оба UUID сверяются под блокировкой токена. HTTP 409 означает изменившуюся пару ключей; повторно откройте метаданные. Удаляется предыдущий ciphertext, ID и срок, текущий ключ не меняется. Проектная/глобальная политика HMAC не ослабляется.

## Журнал безопасности

`GET /api/v1/projects/{project}/security/audit` — проектный журнал для управляющих токенами; `GET /api/v1/system/security/audit` — глобальный журнал для Administrator. Журнал читает существующий `audit_log`, включая исторические события, не создаёт дубликатов. Фильтры `action`, `actor_id`, `target` (UUID), `limit` (1–100), `cursor`. Сортировка `created_at DESC, id DESC`; курсор проверяется внутри той же области и фильтров. Составные цели членства `project:user` видны в журнале, но фильтр `target` принимает UUID точной цели. В ответе только выбранные метаданные, не сырой context. Журнал не предоставляет редактирование/удаление или экспорт. Показывает зарегистрированные действия, а не все HTTP-запросы; не является криптографически защищённым неизменяемым архивом.

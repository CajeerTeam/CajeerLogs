# CajeerLogs 1.0.0 — базовый промышленный выпуск

Историческое руководство по выпуску 1.0.0. Оно описывает процедуру, а не утверждает успешное прохождение внешнего CI. Для актуальной версии используйте [приёмку 1.1.0](Production-Stable-GA-1.1.0.md).

Поддерживаются PHP 8.4/8.5, PostgreSQL 17/18, API v1 и SDK PHP, Python, TypeScript, Kotlin. PostgreSQL остаётся основным хранилищем, ClickHouse 25.8 — необязательной аналитической репликой. Панель и SDK должны соответствовать версии. Для GA требуется один проверенный полный ZIP, итоговый отчёт и подписанные доказательства для одного SHA-256.

## Установка

Получите опубликованный ZIP, `.sha256`, SBOM, отчёт цепочки поставки и итоговый сертификат. Сверьте SHA-256 и аттестации ZIP и `database-certification.json` для тега `v1.0.0`, точного коммита и `.github/workflows/runtime.yml`. Пример проверки и порядок установки: [руководство](Installation.md). Подготовьте отдельную БД, роли, HTTPS, секреты и закрытые метрики; выполните `install:check`, установку, `migrate:status`, `security:audit --tls`, `operations:check`, `operations:triage` и `/ready`. Запустите службы, отправьте подписанное тестовое событие, проверьте поиск, очередь, метрики и восстановление копии.

## Переход с 0.9.9

В прежней версии выполните проверку безопасности и создайте проверенную внешнюю резервную копию. Сохраните старый ZIP, его SHA-256, секреты и конфигурацию. Остановите все записывающие службы и фоновые задания; проверьте новый дистрибутив, совместимость и место. Выполните `php bin/cajeer upgrade BACKUP_ID --confirm-stopped`, затем подтвердите схему, версии, готовность, вход/TOTP, идемпотентность, очередь и архивное хранилище. В 1.0.0 новых миграций нет. Для отката восстановите согласованные старую версию и её исходную копию в изолированную БД, не используйте БД с неподтверждёнными новыми записями.

## Приёмка

Проверяйте безопасность ежедневно и после изменения секретов, контролируйте метрики, оповещения, очереди, хранилища и фактические RPO/RTO. Аттестация ZIP и итогового сертификата обязательна; неподписанный локальный отчёт не доказывает GA. `publish-ga` выполняет публикацию только после проверок, не заменяет уже опубликованные артефакты.
